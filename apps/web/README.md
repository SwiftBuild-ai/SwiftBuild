# SwiftBuild web host

Server-rendered application shell, account screens and same-origin route handlers. Server configuration and sessions stay in server-only modules. The default root workbench uses independent browser-local storage. See [setup](../../docs/self-hosting/README.md) and [API contracts](../../docs/server-api.md).

The `/projects` screen lists authorized workspaces/projects with cursor traversal and explicit create/import/copy actions. `/projects/[id]` authorizes a current snapshot server-side and mounts the editor with a stable storage binding. `ServerWorkspace` saves validated local recovery before any server mutation, sends strong revision tags and retains operation IDs/payloads after uncertain responses. A retained operation is resolved before sending newer edits. Conflicts and access changes stop network writes while preserving subsequent local work. Viewer previews never write to the server.

`BrowserProjectRecovery` stores versioned records in a separate `swiftbuild-server-recovery` database, under user/project keys, with transactional stale-tab rejection. Records retain the latest archive and any uncertain operation archive. They preserve complete checkpoints and run evidence. These keys isolate records; server authorization still comes from sessions and transactional membership checks. Recovery is browser/origin-specific and is not a server backup.

Before mounting an editor, the host inspects recovery and requires an explicit choice when it differs from the authorized snapshot or contains an unresolved different operation. Users can export recovery, create a separate project when authorized, or explicitly discard it and open the current server revision. Each user/project gets a fresh adapter/workbench. Confirmed server save labels are used only when `write` resolves; viewer saves use a local preview label. The account screen can clear confirmed cached copies while retaining unsaved and other-user recovery. Sign-out retains browser recovery; it is not encrypted server storage or a shared-device isolation guarantee.

Revision history exports immutable snapshots without replacing current work. Imports validate complete archives before creation. Copying the saved local draft retains checkpoints and run evidence and leaves local storage untouched; unsaved edits in another tab are not uploaded. Creation retry keys currently survive within the mounted screen; persistence of unconfirmed creation operations across page reload remains planned. Network save retries retain their payload in recovery storage and require an explicit recovery choice on reopen.

Unit tests exercise lost responses, retained operation ordering, conflict preservation, recovery storage failure, viewer previews, uncertain reverted edits, invalid confirmations, native transport binding, selective cache cleanup and transactional isolation. Browser integration must use a real isolated database and the compiled application; the [development guide](../../DEVELOPMENT.md) records how to run verification.
