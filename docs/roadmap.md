# Roadmap

## Implemented engineering workbench

Native format 1.1 and retained 1.0 migration; semantic canvas editing; linked requirements and decisions; workload scenarios; analytical propagation; seeded, bounded topology simulation; evidence-based rules; transactional browser workspaces; immutable checkpoints and validated project archives.

The component library includes 35 named technologies/provider services, 26 cataloged generic infrastructure definitions and the eight retained core primitives. Validated local JSON packs, aliases, favorites, recents, details, keyboard/drag insertion and explicit legacy database conversion are implemented. Neutral black/zinc is the default dark theme, with a retained light preference.

The current engines support declared service, database, cache, queue and router behavior. Unsupported feedback paths, unattributed initial backlog, missing measurements and out-of-range measured curves remain explicitly unevaluated. See [supported models and limitations](engineering/capacity.md).

## Calibration and model extensions

Expand independently tested behavior models, resource-sharing declarations, attributed initial backlog, replication overhead, failure distributions and production measurement ingestion. Each extension needs explicit contracts, provenance and numerical references. Keep existing embedded definitions usable; configuration or port changes require explicit upgrades.

## Separate workstreams

- Server persistence and authorization: injected storage, PostgreSQL migrations and project access controls.
- Collaboration: conflict resolution, shared editing and durable audit history.
- Provider packs and registry: remote distribution, verified publisher identity, additional icon installation and provider-specific calibrated behavior models. Local declarative packs already work.
- Extension SDK, YAML and CLI: adapters around the same validated native model.
- AI assistance: inspectable proposals, evidence and reversible edits.
- Public website and publishing: real repository ownership and a private security reporting channel.

These are future workstreams, not available navigation or empty packages. Prioritize them using contributor proposals and actual user workflows.
