# canvas

Interactive graph adapter and per-instance editor store. Workbench mounts a provider with immutable document history and transient selection. Engineering workflows connect requirements, decisions, scenarios, profiles, findings and checkpoints. The browser simulation worker is cancellable and emits progress, versioned reports and incomplete states.

`WorkspaceAdapter` abstracts asynchronous transactional persistence. IndexedDB saves current work, checkpoint bodies and run summaries atomically with optimistic revisions. Legacy draft migration preserves original localStorage data. `importDocument` enforces 5 MiB native imports; validated project archives use 50 MiB. Invalid data and failed transactions leave work intact and exportable.

`Workbench` accepts a validated `initialArchive`, an optional stable `storage` binding with `createAdapter`, `savedLabel`, `description` and `locationLabel`, and an `onArchiveChange` callback. The host receives the current complete archive after hydration and owns protocol, authentication, unsaved-work warnings and recovery; the canvas remains independent of server identity. Injected storage never reads or migrates the global legacy browser draft. Mount a fresh workbench when changing users, projects or storage bindings. `IndexedWorkspace(factory, key)`, available through `@swiftbuild/canvas/workspace`, can isolate recovery archives by caller-chosen keys; its default `current` key and existing database identity are unchanged. The web host now supplies a server adapter and explicit recovery choices. Local settings open server projects in a new tab so the current draft stays open.

The catalog is the default sidebar; the rail includes a keyboard-accessible object list and engineering destinations. Fresh work is blank; commerce and illustrative engineering examples are explicit templates. Custom components embed validated definitions. Inspector tabs expose configuration, capacity and notes. Connections can be created by ports or the C command. Optional minimap and metric overlays complement the object list. Activity reports actual autosaves; locking changes interaction only. Changes require keyboard, E2E and responsive checks.

The command palette owns transient search independently of the component browser. Actions, components, objects and engineering records have stable command IDs; duplicate component names display definition identities. Search ranks exact, prefix and substring matches, with actions first for equal ranks. Arrow keys choose a result, Enter runs it, and Escape returns focus. Empty results are announced and do not execute a command.

The infrastructure example uses concrete technologies. Registry search covers aliases, taxonomy and capabilities; filters separate technologies, generic primitives, favorites and recent insertions. Definitions can be inspected before insertion, dragged onto the canvas or inserted by keyboard. Local component packs validate before an undoable installation. Configuration exposes unit-aware primary and advanced fields, with resource bindings and explicit legacy conversion. Save status identifies the latest edit generation rather than an older completed write.
